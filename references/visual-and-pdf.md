# 视觉与 PDF 验收

## 版式底线

- A4，默认 1 页，最多 2 页。
- 单栏；不使用侧栏、表格、文本框、头像、图标字体、二维码、技能条或信息图。
- 允许页头和章节标题使用浅、细的 `border-bottom` 横向分割线；`border-radius`、闭合边框、顶边和侧边线声明必须为 0。
- 使用 [六主题系统](style-system.md) 中的主题令牌；用户显式选择 ResumeCollection 参考预设时，改用 [参考目录](resume-collection-catalog.md) 的受控令牌。两条路径都不允许任意拼色造成风格漂移。
- 中文必须实际嵌入主题目标字体；Kami 使用本机已授权的 TsangerJinKai02 W04，W05 可用于标题，其余主题使用本机 Songti SC、PingFang SC 或 Menlo 组合。
- 正文不低于 9pt，姓名 22–26pt，章节标题 10–12pt；行高 1.28–1.42。
- 姓名与联系信息在正文区域；不要放进页眉页脚。
- 颜色对比清楚，黑白打印仍能区分层级；正文不能用浅灰。
- 章节、经历条目尽量 `break-inside: avoid`，但不要为了不分页把字号压得过小。

## 机器检查

1. `scripts/validate_resume.py` 同时检查 JSON、HTML 和 PDF 并通过。
2. `pdfinfo resume.pdf` 显示 A4 附近尺寸、1–2 页、未加密。
3. `pdftotext -layout resume.pdf -` 能读到姓名、邮箱、教育/项目/技能等标准章节。
4. PDF 文件头为 `%PDF-`，正文不是整页图片。
5. HTML 不含外链字体、外链脚本或远程图片；存在横向 `border-bottom` 分割线，但 `border-radius` 与闭合/顶部/侧边边框为 0。
6. `pdffonts resume.pdf` 显示中文正文实际使用并嵌入主题目标字体，而不是仅在 CSS 中声明；Kami 必须出现 TsangerJinKai02。
7. 批量模式必须正好生成六套 HTML/PDF 与一份清单，每个文件的 `data-theme`、核心色和目标字体互相一致。

## 视觉检查

将 PDF 每页转为 PNG：

```bash
pdftoppm -png -r 150 resume.pdf resume-page
```

逐页查看，至少检查：

- 页边距是否均衡，首屏视觉重心是否稳定。
- 姓名、目标岗位、联系方式是否在 5 秒内可读。
- 标题、机构/项目、角色、日期、正文是否有清楚层级。
- 中英文、标点、链接、长技术词是否异常换行。
- 是否存在孤立标题、被切断的 bullet、重叠、截断、底部拥挤或大片空白。
- 两页时第二页是否有明确内容，不出现只有 1–2 行的尾页。
- 六套并排时是否确实形成不同的字体、页头、密度和标题节奏，而不是只换强调色。

发现问题后调整内容优先级、段落长度和间距；禁止仅通过缩小到 8pt 以下“修复”。重新渲染并再次逐页检查。

## 可声称与不可声称

可声称：文本型 PDF、单栏、标准章节、通过本地文本提取、页数/尺寸检查、已逐页目视检查。

不可声称：保证 ATS 通过、保证获得面试、兼容所有招聘系统、关键词匹配率提升、审美优于所有模板。除非有对应平台或人工盲评证据，否则均为 `missing evidence`。
